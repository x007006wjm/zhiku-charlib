# 智库 · SillyTavern 扩展

作者 **if love** · 版本 **0.8.8**。NovelAI 生图、画师库、例图、角色、衣柜、标记生图与共享上传。

## 安装与更新

1. 打开酒馆「扩展」→「安装扩展」。
2. 粘贴仓库地址：`https://github.com/x007006wjm/zhiku-charlib`
3. 安装后刷新酒馆，通过扩展设置「打开智库」、魔棒菜单「智库」或侧边票根打开。
4. 后续在扩展管理里点击更新，再刷新页面。

扩展版不需要酒馆助手。最低宿主版本为 SillyTavern 1.14.0；新版本宿主支持启停钩子，旧版本启停后刷新页面。

**从脚本版切换：先停用酒馆助手脚本库中的旧「智库」，再启用扩展版。** 同一个酒馆用户下，原有画师库文件、图片、NovelAI 设置与共享身份继续沿用，无需重新导入画师库。

## 共享

共享页右上角「＋ 上传」可填写名称、署名、画师串、标签和说明，并附上最多 6 张例图。发布后自动打开「我分享的」。内置共享服务器地址，无需邀请码。已有自定义服务器地址优先使用。NovelAI Key 由使用者自己在酒馆内配置。

## 文生图标记与不发送正则

回复中使用完整标记：

```text
image###1boy, solo, sunset, cinematic lighting###
```

自动使用标记里的提示词调用 NovelAI，结合当前画师串、质量设置及参考图配置；不另外请求聊天 AI 改写剧情。生成结果单独保存在消息扩展数据中，按标记位置显示；原消息与提示词保留，同楼多个标记按顺序生成。普通回复不会自动生图。标记默认显示为收起的「图片提示词」，旁边有「生成图片」按钮，可单独生成该标记；生成中禁用按钮，失败后可点击「重试生成」。魔棒菜单使用 与酒馆一致的单色图片图标。

「生成后自动展开图片」默认开启：刚生成出来的那张图直接展开显示，省一次点击；历史图片、重新打开聊天、切换楼层后仍按收起显示，点「图片 · 点击展开」即可展开，展开后标题变成「图片 · 点击收起」。关掉这个开关就退回「生成完仍是收起的标题，点一下才展开」。自动展开只对本次新生成的结果生效，不会把旧存档里的图片全部摊开。

「开启标记自动生图」默认开启，位于智库设置顶部，也可直接在酒馆的智库扩展设置中切换；关闭选择会保存。开始与结束标记在「文生图标记」中调整。若安装过智绘姬，默认读取它的 `startTag` / `endTag`；否则使用 `image###` / `###`。流式回复在消息完成后识别，不处理尚未闭合的标记。重复消息渲染不会重复生成；切换聊天或改写消息后，不把在途图片插到其他楼层。

内置并自动注册 **「智库 · 生图标记不发送」** 正则：仅过滤发给聊天模型的用户／角色消息文本，保留聊天原文供生图识别。另有「智库 · 生图标记折叠」显示正则，负责折叠块；两条规则都保留编辑原文。修改开始、结束标记时正则同步更新。原有其他正则保留。此功能使用酒馆自带的 Regex 扩展，请保持它启用。

旧的「每楼自动生成」已移除。没有标记的旧楼不会因升级或重新打开聊天而自动扣点。失败时保留标记，可以通过楼层图片按钮重试。

## 角色外观库（本仓库改动）

> 本仓库是在「智库」上加了角色外观库的 **AFPL v9 修改版**（改动清单在本节末尾；原署名与许可见文末「来源与署名」）。

「角色」页给每个角色写「固定外貌」标签（可从角色卡／人设用 AI 抽，也可以自己写），再填**别名**（`|` 或逗号分隔）。之后主 AI 只要在生图标记里写 `$名字$`，智库会在把提示词发给 NovelAI 之前把它换成这个角色的固定外貌：`outfitMode` 为「固定」时连固定衣服一起带，为「跟剧情」时只带外貌。整个过程不额外调用聊天 AI。

### 世界书里怎么用

1. 智库设置里保持「标记里展开 $角色名$」开启（默认开）。
2. 在世界书条目里写一条规则，用宏把本聊天开着的角色列给主 AI，例如：

```text
【配图规则】
生图时角色只写 $名字$，不要自己编外貌。
可用的角色：
{{zhiku_characters}}
```

3. 主 AI 的回复里就可以这样写：

```text
image###$小雪$, cafe, sunset, sitting###
```

`{{zhiku_characters}}` 每个角色一行，形如 `- 小雪（别名：Shirley）[固定服装]` 或 `- 鲍勃[固定，不可改]`；没有开着的角色时是空串。它只列名字与别名、以及两个后缀标记，不把外貌 tag 倒进上下文——外貌由标记里的 `$名字$` 或 JSON 的 `characters[]` 在出图前查库补上。

### JSON 生图标记（`image###{…}###`）

标记内容如果以 `{` 开头且能解析成 JSON，就按结构化标记处理（否则仍走纯文本 + `$名字$`）：

```text
image###{"tag":"2girls, medium shot, rooftop, sunset","nl":"Two girls on a rooftop at sunset.","characters":[{"name":"小雪","tag":"girl, smiling, standing","nl":"the left girl"},{"name":"三年级队长","tag":"girl, short brown hair, surprised","nl":"the other girl"}],"size":"landscape"}###
```

- Base = `tag` + `, ` + `nl`（空的跳过），再照常接画师串/质量词/负面。
- `characters[]` 按名字查库（顺序同 `$名字$`：本楼层本聊天档案 → 开着的全局角色 → 其余全局角色，别名、忽略大小写）。查到的角色：保留 AI 写的开头身份 tag（带括号）与性别 tag，把库里的固定外貌（`fixed` 时连固定衣服）插在它们之后，再接其余 tag，去重；`1girl→girl`、`1boy→boy`、`2girls`/`multiple girls` 这类计数在角色 caption 里删掉。查不到的角色原样使用。
- 角色 caption = 最终 tag + `, ` + `nl`，作为 NovelAI 的 Character Prompt 发送（`use_coords: false`、center 0.5/0.5、顺序保留）；v3 模型与「用酒馆 key」的代理模式不支持分角色，会自动把 caption 接回 base。
- `size`：`portrait` 保证高 ≥ 宽、`landscape` 保证宽 ≥ 高；与当前设置不符时只对这一次请求交换宽高。
- 命中角色的 `charRef`（长相参考）会和出场角色的一起带上，去重。
- 记录里存的是可读的最终提示词（base + 各行 caption），消息里的标记原文不变。
- 全角冒号/逗号/括号在字符串外也能容忍。

### 两层库：全局 / 本聊天

- **全局库** = 「角色」页里的角色（存在 `piaoce_data.json` 的 `characters`）。AI 不能改：只在全局库里的角色是「固定」的，回复里对它的 `<人物>` / `<外貌变化>` 会被忽略（控制台记一条）。
- **本聊天库** = 只在当前聊天有效的档案（存在当前聊天的 chatMetadata `zhiku_chat_chars`，跟聊天一起走）。`$名字$` 的查找顺序是：本楼层的本聊天档案 → 本聊天开着的全局角色 → 其余全局角色。
- **字段级合并**：本聊天档案与**同名**全局角色逐字段合并——本聊天的 `appearance`、`nl`（描述）为空时用全局的；服装在本聊天档案既没有服装、也没有显式的 `outfitMode`（没手动设过「固定」或「跟剧情」）时用全局的；`aliases` 取两边并集；`charRef` 先用本聊天的，没有再用全局的。「本聊天角色」页里会标出每个字段来自哪一层。
- 「角色」页 →「本聊天角色」→ 管理：新建 / 编辑 / 删除、看变更历史并「回到这里」、把本聊天角色「提升为全局」，或把全局角色「复制到本聊天」（复制后 AI 才能改它）。
- **手动编辑 / 回滚 / 删除不丢历史**：手动保存时，这个名字在各楼层里的自动变更会先转成字段级历史记录（`field` / `from` / `to` / `reason` / `floor` / `at`），和已有历史、一条「手动」记录（`floor: -1`）一起写进档案，最多保留 50 条；然后才清掉各楼层的 ops，所以手动值不会被重放覆盖，历史也看得到。回滚的原因记作「手动回滚」。删除时历史随条目一起丢弃。

### 从回复自动建档：`<人物>` / `<外貌变化>`

主 AI 在回复里写这两种块即可，不用另调接口：

```text
<人物>
名字: 爱丽丝
别名: Alice|小爱
外貌: 1girl, long blonde hair, blue eyes, slim
描述: A slim girl with long blonde hair and blue eyes
衣服: white blouse, pleated skirt
</人物>
<外貌变化>
名字: 爱丽丝
加: short hair, black hair
去: long blonde hair
描述: A slim girl with short black hair and blue eyes
原因: 剪短染黑
</外貌变化>
```

- 全角冒号、全角逗号、全角尖括号都认。
- `描述:`（可选）是该角色的英文自然语言描述 `nl`：`<人物>` 里写初始描述，`<外貌变化>` 里写新的完整描述。JSON 标记里它接在角色 caption 的 tag 之后、AI 自己写的 `nl` 之前；纯文本 `$名字$` 只展开 tag，不带描述。全局角色和本聊天角色都有这个字段，角色页 / 本聊天角色页可以编辑，分享、导入、复制到本聊天、提升为全局都会带上。
- `<人物>` 的 `衣服` 可省略；写了就当固定着装（`outfitMode=fixed`）。
- `<外貌变化>` 还接受 `外貌:`（整串替换）、`衣服:`（换固定着装，或写 `衣服: 跟剧情` 切回跟剧情）。已经存在的角色再收到 `<人物>`、或没建档的角色收到 `<外貌变化>`，都不会生效（控制台有记录）。
- 这些块**不写进聊天库基线**，而是记在**那条消息**上（`msg.extra.zhikuCharOps`，带 swipe；每条 op 还记着块在消息里的起始位置 `pos`）；重复渲染不会重复写。
- 块默认从发给聊天 AI 的文本里过滤掉，显示时折叠成「角色档案」，聊天原文不动。

### 按楼层生效

角色状态 = 本聊天基线 + 第 0 楼到**这一楼**（含本楼）的变化。所以：

- 同一段回复里先建档、后面的生图标记就能用新角色。
- 某楼「剪短染黑」之后，重画它之前的楼层仍用当时的旧外貌。
- 滑动（swipe）到别的分支时，swipe 不匹配的变更自动忽略。
- **同一楼内按位置生效**：`<人物>` 对整楼生效（排在它前面的标记也能用到这个角色）；`<外貌变化>` 只对**起始位置在它之后**的标记生效，排在它前面的标记仍看到变化之前的状态，之后的楼层看到全部。标记控制器会把每个标记的起始位置连同楼层号一起交给展开逻辑。没有 `pos` 的旧 ops 保持原行为（整楼生效）。状态按「第 N−1 楼的缓存状态 + 本楼局部 ops」算，并按 (楼层, 位置) 缓存，不会为每个标记重放整段聊天。

推荐的完整世界书条目（宏 + `$名字$` + 两种块）：

```text
【配图规则】
1. 生图时角色只写 $名字$，不要自己编外貌。
2. 本聊天可用的角色：
{{zhiku_characters}}
3. 角色第一次正式出场时，用 <人物> 建档（名字/别名/外貌；固定着装可写「衣服」）；
   之后外貌发生永久变化，用 <外貌变化> 报 加 / 去 / 原因。
4. 标了「固定，不可改」的角色不要发 <人物> / <外貌变化>。
```

### 规则

- 名字与别名匹配都 trim、忽略大小写；顺序是本聊天库 → 开着的全局角色 → 其余全局角色。
- 展开只影响发给 NovelAI 的提示词；聊天里的标记原文不变，图片记录里存的是**展开后**的完整提示词（方便回溯）。
- `$…$` 匹配不到角色时只去掉 `$` 保留原文，并在控制台写一条调试日志，不弹提示。
- 关掉「标记里展开 $角色名$」后，`$名字$` 原样发送；关掉「从回复自动建档 / 记录外貌变化」后，块完全不解析、也不写消息。

## 0.8.8 改动

- 画师串原样保存：存进画师库或「整串改写」时，`{}` `[]`、`1.2::a, b::` 这类写法、顺序和小数位都按你写的原样保存和发送，不再拆开改写成 `1.1::artist:x::`；手动改回的权重也不会再被改回去。用 ± 按钮调权重、加删画师后才会按新内容重新拼。以前已经被改写的画师组，用「整串改写」贴一次原来的串就恢复了。
- 衣柜新增「从穿搭管理器导入」（[Outfit-Manager](https://github.com/wenshui012/Outfit-Manager)）：可以直接读同一个酒馆里装着的穿搭管理器（后端 / 浏览器存储都认），也可以选它导出的 .json（完整备份、只 User、单个角色、全部角色都行）。每组可以选给哪个角色或只存进衣柜，同名角色自动对上。文字描述用 AI 转成标签，配饰自动分到配饰栏，套装里的单品一起带上；只有图的可以用 AI 看图。只读不写，重复导入会跳过已经导过的。
- 氛围编码失败（NovelAI 返回 500 等）时不再让整张图失败：这张先不带氛围出图，并提示是哪张氛围图没编上。编码前统一转成 PNG，遇到 5xx 自动再试一次。
- 设置里点「测试」时，如果这台设备连不上查余额的 api.novelai.net（Failed to fetch），改成提示「查不到余额，去生图页试一张」，不再显示成连不上。
- 负面预设加「自定义」：自己写一段固定负面，每次出图都加在负面最前面（生图页、聊天标记出图、例图、试穿都带上）。第一次选会先放进原来预设的内容，在它基础上改。
- 修复手机上配合部分美化时，智库窗口只显示上面一截、背景透明、透出后面聊天的问题。窗口和弹窗改挂到页面最外层，层级抬到最高，背景不再跟着美化的颜色变量变透明。

- 角色卡绑定画师串：进入该角色的聊天自动切换；离开到没绑定的角色时，换回绑定前在用的画师串。

- 角色参考只在「角色」页给每个角色单独绑（建组、加图、调「像不像」都在那里）；标记生图时按出场角色带上，没绑就不用。氛围页只管氛围。

## 生图队列

手动点击仅生成对应标记；多个标记时楼层入口提示选择具体按钮。每张独立显示排队、生成、保存状态。智库内普通生图、局部重绘和氛围编码共用串行队列，请求间隔至少 1.5 秒；429 按 Retry-After 或 5/10 秒退避，最多重试两次。用酒馆里的 NovelAI key 时，酒馆会把 429 报成 500，这种情况同样等待后重试。当前队列仅协调本页面智库，不包含智绘姬的跨设备云端队列。
